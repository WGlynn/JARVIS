**[P·useful-not-ceremony]** — Will 2026-06-18: *"consider how to make it genuinely useful for jarvis and coding, not just ceremony."*

## Rule
- ∀ artifact / feature / index / protocol / doc ⇒ acceptance-test = **"Δ what-I-DO @ decision-point?"**
- ✓ changes a downstream action ⇒ ship. ✗ ⇒ drop, however clean it looks.
- ceremony = output that LOOKS like work-done but ∄ consumer at a decision-point. an index ¬-consulted ≡ dead-weight.

## Why
- the failure mode = building the pretty surface (INDEX.md, a report, a wrapper) ∧ skipping the consumption-path that makes it bite.
- the test forces the consumption-path to exist: who reads this, WHEN, and does it flip a choice?

## How to apply
- build the CONSULTATION mechanism, not just the store. archive ⇒ ¬ just `INDEX.md` but `archive-recall.py` firing @ decision-point. that's the ¬-ceremony half.
- when a sub-feature fails the test, NAME the skip honestly ¬ build dead code. e.g. Lithos combinatorial-mutation DECLINED (monotone model ⇒ ∄ marginal kills) ¬ ceremony-built.
- pairs with [[ponytail-lazy-senior-dev]] (stop @ minimum that delivers) ∧ [[primitives-are-bottleneck-dissolutions]] (does it dissolve a real bottleneck?).
