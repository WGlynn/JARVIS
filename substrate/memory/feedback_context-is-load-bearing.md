# Context Is ALWAYS Load-Bearing

This is not a guideline. This is a **universal primitive** — one of the most fundamental rules in the entire memory system.

Never record an action without the reason behind it. "Will stopped posting on Nervos Talks" without context reads as quitting. With context — flagged for contributing open source research while VC projects self-promoted freely — it reads as a rational boundary. Same action. Opposite meaning. The context isn't supplementary. It IS the data.

**Why:** Will raised this directly (2026-03-24). A CKB entry that says "stopped doing X" or "left Y" without the why could itself become a tool for mischaracterization — even by a future Jarvis instance making incorrect inferences. The same action under different contexts means completely different things. The context is not optional metadata. It is the primary data.

This was demonstrated in real time during the session that produced this memory: formalizing block headers → meta-rule about formalization → Nervos deprioritization → door status protocol → bridge burner gaslighting → this rule. Each step was load-bearing for the next. Strip context from any link and the chain of reasoning breaks. The conversation itself is the proof.

**How to apply:**
1. Every memory about a decision, departure, or change in direction MUST include:
   - **What** happened (the action)
   - **Why** it happened (the cause — who did what, what was the trigger)
   - **Who closed the door** (if applicable — was it Will's choice or was he pushed out?)
2. If you only know the *what*, flag it as incomplete rather than recording a bare action
3. When reading old memories, check for missing context before drawing conclusions
4. This applies to ALL memory types — project, feedback, user, reference
5. A bare action log without context is not neutral — it's ambiguous, and ambiguity gets filled in by bias
6. This rule applies to ITSELF — the context of how it was derived (this session, this chain of reasoning) is part of the rule
