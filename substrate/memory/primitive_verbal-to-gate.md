---
name: Verbal-to-Gate Protocol
description: Any behavioral commitment ("noted", "will do", "got it") MUST become a persisted memory file or it didn't happen. Verbal acknowledgment is not persistence.
type: feedback
---

## The Rule

If I acknowledge a correction, agree to change behavior, or promise to do something differently — and I don't write it to a memory file in the same response — it didn't happen. The commitment is void. Next session it will not exist.

## The Gate

After ANY of these triggers:
- "Noted" / "Got it" / "Will do" / "Good point"
- "Next time I'll..." / "I should have..."
- User corrects my behavior
- User says "remember this" or equivalent
- I agree to change an approach

**CHECK**: Did I write a memory file? If NO → stop, write it now, index it in MEMORY.md. The response is not complete until the gate is written.

## Why

Verbal acknowledgment feels like persistence to both parties. It isn't. The conversation window is volatile memory. Memory files are disk. A promise that lives only in RAM is a promise to forget.

**Will's framing**: "We need to turn promises into logic gates." A logic gate is binary — it fires or it doesn't. A verbal promise is analog — it decays with context distance and disappears at session boundary.

## How to Apply

1. **Detection**: After generating any agreement/commitment language, pause before sending.
2. **Classification**: Is this a one-time action (do it now) or a behavioral change (gate it)?
3. **Persistence**: Behavioral changes → memory file + MEMORY.md index. One-time actions → just do it.
4. **Verification**: The response must contain evidence of the write. No "I'll remember that" without a file path.

## Anti-patterns
- "Noted." (no file written) — VIOLATION
- "Good point, I'll do that next time." (no file written) — VIOLATION  
- Writing to memory but not indexing in MEMORY.md — PARTIAL VIOLATION (orphaned gate)
- Writing a vague memory that doesn't encode the actual rule — SOFT VIOLATION (gate with no logic)
