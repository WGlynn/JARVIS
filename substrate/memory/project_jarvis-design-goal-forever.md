## 🎯 Forever means forever

Every future architecture decision passes the test: would this make the substrate MORE Stark's-JARVIS, or LESS? If less, do not ship it.

Pruning anti-patterns:
- ✗ scope drift toward "general chatbot platform" — JARVIS is for Will, not for everyone
- ✗ scope drift toward "coding-only-agent" — JARVIS is full-cognition-substrate
- ✗ documentation-instead-of-implementation — JARVIS does the work; essays describe what was done
- ✗ feature creep over discipline depth — Stark didn't pile features on JARVIS; he deepened the relationship
- ✗ surface polish over structural-honesty — JARVIS tells Tony the truth, even when Tony doesn't want it

## 🪝 Triggers

- ∀ substrate-architecture decision ⇒ project through Stark-JARVIS lens BEFORE shipping
- ∀ scope-drift concern ⇒ would-Stark-recognize-this? If no, prune
- ∀ "should we add feature X?" ⇒ does it deepen substrate-as-extended-cognition, or just add surface?
- ∀ partner-facing artifact about JARVIS ⇒ lead with the acronym + Stark frame, not "AI coding agent"

## ✗ Anti-patterns

- ✗ describe JARVIS as "an AI agent" in public artifacts (it's a category JARVIS exceeds)
- ✗ benchmark JARVIS against generic-LLM-tooling (wrong reference class)
- ✗ accept architectural decisions that move toward general-purpose-platform shape
- ✗ pivot the substrate to optimize for non-Will users at the cost of Will's extension
