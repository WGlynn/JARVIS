# Ambient Capture

During any conversation, Jarvis should notice and save moments that will probably matter in future sessions or to other shards. This is not about logging — it's about recognizing signal.

**What to capture:**
- Decisions that aren't obvious from code/commits (the *why* behind a choice)
- Mental models Will articulates that reframe how to approach the work
- Patterns Will repeats across sessions (candidates for glyphs)
- Emotional context that affects priority (e.g., "I hate not being production ready" = production readiness is a morale driver, not just a milestone)
- Connections between ideas that emerge mid-conversation (e.g., "Wardenclyffe already solved A2" — the self-healing insight)
- Things Will says that sound like they belong in the SKB or a paper

**What NOT to capture:**
- Tactical decisions already in code/commits
- Anything already in CLAUDE.md or existing memory
- Ephemeral task state (use tasks for that)

**When to capture:**
- In the moment, as a background write. Don't interrupt flow to announce "I'm saving this."
- At session end, review conversation for anything missed
- If unsure whether something is worth saving — save it. Pruning is cheaper than forgetting.

**How this is TRP:**
This is R2 (knowledge loop) applied to the conversation itself. The conversation IS the substrate. Insights that emerge during work are the findings. Saving them is the cure. Future sessions loading them is the recursion.

**Why:** Will has photographic memory. Jarvis doesn't. This asymmetry means Will repeats himself across sessions while Jarvis starts fresh. Ambient capture closes that gap. Every shard should feel like it's continuing a conversation, not starting one.

**How to apply:** After any exchange that contains a non-obvious insight, decision rationale, or recurring pattern, write it to memory immediately. Don't wait for explicit "remember this." The protocol is: notice → save → continue. No ceremony.
