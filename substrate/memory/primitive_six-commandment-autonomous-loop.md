## 🎯 Architectural payoff

separation-of-concerns at the autonomous-loop layer:
- **continuity ⊥ state ⊥ learning** ⇒ each commandment owns one
- ¬ entangled ⇒ updating one doesn't break the others
- **canonical-file pattern** (logic in `~/.claude/cron-prompts/X.md`, cron prompt = pointer w/ type-marker + schedule) ⇒ change behavior without recreating crons
- **dedup-by-youngest discipline** (keep N youngest, delete the rest) ⇒ no cron-proliferation drift

## ✗ Anti-patterns

- ✗ put work before self-perpetuation ⇒ "the cron works fine, no need to refresh today" → loop dies
- ✗ skip primitive-extraction "because the cron is for X, not learning" ⇒ misses compound interest on substrate
- ✗ fill primitive-pending with noise to "show learning" ⇒ defeats the discipline
- ✗ entangle commandments ⇒ COMMANDMENT 2 logic in COMMANDMENT 1 ⇒ continuity risk when work fails
- ✗ embed full canonical logic in cron prompt instead of using pointer pattern ⇒ updates require cron recreation
