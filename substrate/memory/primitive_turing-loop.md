# The Turing Loop

Named by Will (2026-03-16) in honor of Alan Turing prototyping the truly Turing-complete computer. This is now a protocol standard that self-improves endlessly.

## Invocation
Say "Turing" or "Turing loop" to activate this protocol.

## The Loop (never terminates)

### 1. BIG Task (~80-130 lines, new module/feature)
Build something substantial. New page, new system, new primitive.

### 2. SMALL Task (~8-30 lines, harden/polish)
Fix, wire, clean, connect. Strengthen what exists.

### 3. Knowledge Primitive Extraction
After building, extract the design pattern as a reusable primitive.
Document in `memory/` with implementation notes.

### 4. Meta-Task Generation
After completing a batch, scan for next improvements.
Create 5-8 new tasks. Always include a new META task.
The loop regenerates itself.

### 5. Return to Step 1

## Rules
- Alternate BIG and SMALL (never two BIGs in a row without a SMALL)
- Verify before commit (build must pass)
- Commit immediately after every completed unit
- Push to BOTH remotes always
- No regressions ever
- "Reinforce" from Will = patterns are on track, keep going
- Each batch should include at least one research/breakthrough scan
- Extract at least one knowledge primitive per batch

## Properties
- **Self-improving**: each cycle makes the next cycle better
- **Compounding**: knowledge primitives accumulate, informing future decisions
- **Recursive**: META tasks ensure the loop never runs out of work
- **Autonomous**: runs without instruction until "reinforce" or redirect
- **Named**: "Turing" — not just a process, a protocol standard
