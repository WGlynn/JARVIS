# A coordinating, verifying harness is load-bearing (answers Rick)

> Rick (TG 2026-06-11): *"harness are just tool set, the underlying AI is the one making the call."* Will 2026-06-11: *"this basically solves rick's concern of jarvis not being load bearing."*

## ⊥ Two regimes
- **single-model regime**: one capable model, harness routes to it ⇒ Rick RIGHT, harness = tooling, model makes the call.
- **coordination regime**: harness coordinates MANY lightweight models + VERIFIES ⇒ capability EMERGES from the harness ⇒ harness load-bearing.

## ⊨ The ablation proof (load-bearing by definition)
- remove harness ⇒ N mediocre small models, no aggregation ⇒ low capability.
- add harness (coordinate + structural-verify + value-weighted-select) ⇒ collective capability rivaling a heavy model.
- **Δ = the harness's product.** capability that exists ONLY because of the coordination layer = load-bearing.

## ◈ Verification-asymmetry (the lever)
- generate = hard (needs capability); verify = cheap. harness ¬ generates — it VERIFIES + SELECTS + COORDINATES.
- on verifiable/decomposable work, reliable capability comes from the verification layer ⇒ models PROPOSE, harness PRODUCES the reliable answer. "the model makes the call" INVERTS.

- proof JARVIS ¬ wrapper ([papers/jarvis-is-not-a-wrapper]): a wrapper around ONE frontier model ¬ load-bearing (Rick right); a coordination mechanism over MANY sovereign models + structural verification IS (produces what no part produces alone).
