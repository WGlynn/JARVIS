**Rule**: When Will explains a process, gives a preference, or we converge on a good workflow — codify it as a memory/primitive/skill immediately, even if the task is low-frequency.

**Why**: Will, 2026-04-17: *"every protocol you add, you remove the need to repeat a new process ever again."* The value of protocolization isn't "this task happens often" — it's that one save permanently eliminates the re-explanation cost across all future sessions. Memory is cheap; re-deriving process from conversation is expensive and error-prone.

**How to apply**:
- Don't gate protocol-creation on "is this task frequent enough?" — gate it on "did I just derive a process that could be re-invoked by a short phrase?"
- If Will articulates a preference or workflow (even casually), write it down. Don't wait for him to say "save this."
- Prefer trigger-phrases that map to procedures (e.g., "clean desktop" → routine) — these are the highest-leverage form because they compress a whole workflow into ~2 words.
- Related primitives: [Verbal→Gate](primitive_verbal-to-gate.md) (noted without a file write = violation), [Named=primitive](feedback_named-protocols-are-primitives.md), [Habit Detection](primitive_user-habit-detection.md) (2 asks = gate).

**Corollary**: Over-protocolizing is cheap. Under-protocolizing costs every future session. Err toward save.
