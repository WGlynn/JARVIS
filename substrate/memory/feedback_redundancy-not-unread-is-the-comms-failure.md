**[F·redundancy-not-unread-is-the-comms-failure]**

∀ contribution → shared partner thread ⇒ read prior exchange FIRST.
Cost-fn = mutual-repetition, ¬ unread-volume.

> *"if you wrote something I didn't read, that's not a problem on its own. It's only when we start repeating each other that it's a problem."* — Will 2026-06-18
> *"possibly one of the most useful comms primitives I've made so far."*

**Why** (the asymmetry = the insight):
- unread material ≡ latent-option · cost=0 · maybe-never-needed ⇒ ✗ problem
- re-explain what other-party already said/conceded ⇒ negative-signal ("didn't read your reply") ∧ wastes partner-attention ∧ stalls thread in loop ¬ advance
- ∴ repetition-between-parties = failure · unread-alone ≠ failure
- ≡ [[repetition-is-useless]] lifted: intra-agent turn-output → cross-party human-in-loop
- rule: Δ(my-contribution, already-established) > 0 ∨ STOP

**How to apply:**
- ∀ partner-facing contribution → ongoing thread (ethresearch / email-chain / TG / GitHub / doc-handback) ⇒ FETCH + read actual prior posts (¬ search-snippet)
- enumerate settled/conceded/agreed ⇒ build FORWARD from latest-open-point
- ✗ restate established ground
- deliverable-value ≡ Δ over existing-exchange
