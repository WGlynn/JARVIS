---
name: Discretion in public-facing documents
description: Never include embarrassing personal details about contacts/partners in public repos or docs — generalize private anecdotes
type: feedback
---

Never broadcast specific embarrassing details about contacts in public documents (repos, docs, overviews). If someone shared a personal story (like a financial mistake), reference the *category* of experience, not the specific incident.

**Why:** People are embarrassed by mistakes. Putting "Martin lost USDC to wrong address" in a public GitHub doc is insensitive and could damage a relationship. Private memory can note "has personal experience with X" without specifics.

**How to apply:** When writing docs for/about specific people — especially partnership leads — generalize personal anecdotes. "Anyone who's been in crypto long enough has seen X" instead of "You experienced X." Keep specific details in private memory only, and even there, be discreet.
