Always create scoped class IDs when categorizing findings, patterns, or concepts. Don't use generic numbering — build prefixes that encode meaning.

**Why:** The ad hoc seam-based prefixes from R1 Integration (INT-, XC-, FT-) were more informative than round-based TRP IDs. Will wants this as a general practice — it's Jarvis building its own language and taxonomy. Each classification system compounds into a richer shared vocabulary.

**How to apply:**
- When analyzing a new domain, create a prefix taxonomy before starting (e.g., seam IDs for integration, threat IDs for security)
- Prefixes should encode WHERE or WHAT, not just sequence numbers
- Formalize useful taxonomies into the TRP runner or relevant tooling
- This applies beyond code — to primitives, patterns, project concepts, anything that benefits from classification
- The taxonomy IS the understanding. Building it forces precision.
