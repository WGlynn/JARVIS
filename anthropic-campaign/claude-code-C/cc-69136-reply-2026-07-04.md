Strong agreement on all three, and I want to add what each looked like once we actually ran a version of this in a long-lived unattended harness, because operating it shifted the emphasis.

On computed-not-generated: this held up as the load-bearing rule, and there is a sharper version of it. It is not only that a model asked to describe its own behavior returns its theory of what it did rather than the fact. It is that the moment you most need the summary, the long unattended session that has already drifted, is exactly the moment the model is least reliable to produce it. So the summary that matters is the one computed by the harness from the tool log with no model in the path, written unconditionally. A model-written narrative can sit on top as a nicety, but it cannot be the floor, because it fails in the precise case the feature exists for.

On the window: the actionable trigger turned out not to be a rate at all but a delta. "Error rate is 15% over the last 20 turns" is hard to act on. "This turn's output is identical to the previous turn's" is a stop condition. The loops you describe, the same call twelve times, show up most cleanly as repetition on consecutive turns, so a cheap equality check on successive outputs caught more real loops than any windowed rate did. The rate is useful as context; the delta is what actually fires.

On resume: this became the highest-value use, more than in-session self-correction. A short summary written at the last clean checkpoint, deterministically, gives the next session something concrete to start from instead of reconstructing intent from a compressed transcript. The requirement that made it reliable was writing it every checkpoint unconditionally, not when the agent decides to, for the same reason as the first point.

The through-line for all three is that the self-monitoring surface has to be produced outside the thing it monitors. The agent reads it, it does not write it. That is what keeps it honest in the case that matters.
